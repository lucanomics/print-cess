# Threat model

## Scope and security goals

The protected asset is a visitor's document from mobile selection until physical collection. The
primary goals are: server-side systems cannot normally decrypt it; one QR is claimed once; one
payload is consumed and submitted at most once; every terminal path converges on deletion; and no
document identifier appears in application logs or the next visitor's UI.

Trust boundaries are the visitor's mobile browser, Vercel-delivered JavaScript, Route Handlers,
Upstash services, Private Blob, the managed Windows kiosk, the document parser/renderer, Windows
spooler/driver, the printer, and the public counter. TLS, provider control planes, the kiosk OS, and
the deployed binaries are dependencies, not assumptions erased by application encryption.

## Threat analysis

| Threat                         | Attack path                                                                               | Mitigation                                                                                                                                    | Residual risk                                                                                                                                    | Operational requirement                                                                                     |
| ------------------------------ | ----------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------- |
| QR theft                       | Photograph or remotely share an unused QR; use bearer fragment first                      | 256-bit token, three-minute TTL, atomic first claim, hide QR after claim, no manual code                                                      | An attacker who sees the live QR can win claim and cause denial of service; no visitor identity is authenticated                                 | Place display away from remote cameras; verify auto-rotation and used-QR message daily                      |
| QR replay                      | Reopen history/screenshot or submit the same fragment twice                               | Claim-once state transition, terminal state immutability, token hash only, fresh kiosk key/session                                            | Browser history or screenshots may retain fragment on the phone                                                                                  | Mobile code clears visible fragment; never print or photograph QR for support                               |
| Two-phone race                 | Concurrent claim requests with the same QR                                                | Redis Lua/revision CAS permits exactly one `waiting -> claimed`                                                                               | Provider/network retries still produce conflicts visible to the losing phone                                                                     | Run contention tests against approved Redis; alert only on aggregate anomaly                                |
| Server operator reads file     | Read Route Handler traffic or Blob object; substitute public key                          | Ciphertext bypasses functions; ECDH private key stays at kiosk; fingerprint is QR-bound                                                       | A malicious web deployment can exfiltrate plaintext before encryption; an operator controlling both QR display and web code can defeat the model | Protected deployments, reviewed hashes/build provenance, CSP, least privilege, change approval              |
| Blob URL disclosure            | Signed URL appears in logs, referrers, crash reports, browser extension, or clipboard     | Exact random pathname, one operation, short expiry, Private Blob, redaction, no analytics, `Referrer-Policy: no-referrer`                     | Holder can perform the permitted operation until expiry; provider may log URL/IP                                                                 | Treat URL as a credential; prohibit full request logging and support screenshots containing URLs            |
| Signed PUT reuse               | Replay PUT or overwrite after upload                                                      | One PUT delegation, random path, `allowOverwrite: false`, size/type limits, commit one ETag                                                   | Provider enforcement needs credential-backed verification; races may exist around completion callbacks                                           | Preview integration test replay/no-overwrite and compare committed ETag before GET                          |
| Signed GET reuse               | Fetch ciphertext repeatedly before expiry                                                 | GET issued only after consume, exact path/op, shortest practical TTL, immediate delete, cache bypass                                          | Leaked ciphertext can be retained indefinitely, though not decrypted without kiosk key                                                           | Do not log URL; monitor cleanup lag; erase kiosk session key after terminal state                           |
| Signed DELETE abuse            | Delete another object or race an overwrite                                                | Exact path, delete-only token, conditional `ifMatch` ETag                                                                                     | Deletion can deny service for that one object; provider semantics remain to be verified                                                          | Test not-found, wrong ETag, replay, and concurrent cleanup in Preview                                       |
| Session brute force            | Guess session IDs or bearer tokens; enumerate status                                      | At least 128-bit IDs and 256-bit tokens, hashes at rest, generic responses, rate limits                                                       | Public status timing may reveal aggregate service use; distributed DoS remains                                                                   | WAF/rate policy and abuse thresholds require approval and load test                                         |
| Token leakage                  | Query strings, logs, analytics, error messages, or Redis expose bearer                    | Fragment-only upload token, independent kiosk token, hashes in Redis, no-store, structured redaction                                          | Compromised mobile/kiosk memory or browser extensions can read active token                                                                      | Disable third-party scripts/extensions; rotate registration/admin credentials; review logs                  |
| Ciphertext tampering           | Change header, key, IV, salt, ciphertext, or tag                                          | Whole header plus session/fingerprint in AES-GCM AAD; strict length/version parser; authenticate before parse                                 | Repeated tampering can cause denial of service                                                                                                   | Negative vector suite and redacted C-series event counters                                                  |
| Malicious PDF                  | Parser/renderer exploit, active actions, decompression bomb, malformed cross-reference    | Magic/type checks, size/page/encryption validation, no JS/OpenAction/Launch/attachments/external links, bounded renderer                      | Native/library vulnerabilities and complex PDFs remain high-impact on kiosk                                                                      | Patch SLA, parser sandbox/least privilege, representative fuzz corpus, library security review              |
| Extension/MIME disguise        | Rename executable/HTML/SVG/ZIP as PDF/JPG/PNG                                             | Ignore filename/declared MIME as authority; magic bytes plus full parser/decoder validation; metadata match                                   | Polyglot formats can exploit parsers                                                                                                             | Maintain adversarial fixtures and update format detectors with parser updates                               |
| Large/decompression input      | Oversized PUT, huge image dimensions, compressed PDF/image bomb                           | 10 MiB plaintext and 10,485,911-byte envelope cap, signed PUT cap, bounded download, page/dimension/decode budgets                            | A small compressed object can still expand heavily; concurrent sessions can exhaust service                                                      | Define dimension/pixel/time/memory limits and load-test before approval                                     |
| Service denial                 | Flood create/claim/status, exhaust Redis/Blob/QStash, jam printer                         | Rate limits, short TTL, one object/session, timeouts, bounded concurrency, printer backpressure                                               | Public endpoint and physical printer remain finite resources                                                                                     | WAF/provider quotas, network monitoring, and a service-disable runbook                                      |
| Kiosk escape                   | Keyboard shortcuts, dialogs, shell crash, admin route, removable media                    | Standard account, Shell Launcher where supported, AppLocker/GPO, Keyboard Filter where supported, no print dialog, hidden authenticated admin | Shell Launcher alone is not a complete sandbox; physical access and OS vulnerabilities remain                                                    | Institution-managed Windows image, separate admin account, port/BIOS policy, annual escape test             |
| Next-user disclosure           | Stale completion/preview, back navigation, crash state, temp file, memory reuse           | Phone holds preview; kiosk never displays document; 15-second reset, fresh key/session, startup temp cleanup, no filenames/logs               | RAM, crash dump, page file, or OS thumbnails may retain data                                                                                     | Disable crash dumps for content process, encrypted disk, approved paging policy, reset observation test     |
| Abandoned print                | Visitor leaves output in tray; another person takes it                                    | Large completion prompt, arrow, sound, one-copy policy, short dwell                                                                           | Software cannot ensure physical collection                                                                                                       | Counter layout, privacy tray if available, documented staff disposal procedure                              |
| Spooler/driver residue         | Plaintext pages remain in spool files, driver cache, printer storage, or job history      | No application plaintext file; one named queue; immediate app cleanup; restrict queue/history                                                 | Windows, driver, and printer firmware may persist render data beyond app control                                                                 | Approve spool policy, disable job retention where possible, test exact driver/model, secure printer storage |
| Application crash              | Key/plaintext references survive; object/session orphaned; restart resubmits              | Session key not persisted, startup cleanup, consumed/printing never auto-resumed, QStash + orphan sweep + TTL                                 | Managed memory/page file/crash dump can retain bytes; ambiguous job may have printed                                                             | Crash tests at every state; monitor cleanup; no automatic print retry after restart                         |
| Duplicate print                | Repeated consume, API retry, double click, process recovery, spool timeout                | Atomic consume-once, print idempotency key, one entry to submission, disable reprint, fail closed on ambiguity                                | A buggy/hostile driver could duplicate internally; staff manual retry can duplicate                                                              | Train staff not to retry P-04; inspect queue/output before authorizing a completely new session             |
| Cleanup race/failure           | QStash callback overlaps consume/terminal cleanup; provider outage; Redis TTL fires first | Terminal seal plus path/ETag/revision checks, idempotent delete, explicit cleanup, delayed message, orphan ledger/sweep                       | Provider backup/log retention and prolonged outage can extend ciphertext metadata lifetime                                                       | Cleanup-lag alert, bounded admin sweep, provider retention review                                           |
| Provider logs                  | Vercel/Upstash/QStash record IP, UA, timing, path, payload metadata, or URL               | Random path, no filename/content, small pseudonymous payloads, application logging disabled/redacted                                          | Provider-controlled telemetry is outside complete application control                                                                            | Contract/DPA, region and retention approval, support-access audit                                           |
| Printer status spoof/ambiguity | Driver reports ready/submitted inaccurately or loses acknowledgement                      | Capability/status checks, named printer, single submit boundary, no retry on unknown                                                          | “Submitted” does not prove paper output; status enums are driver quality dependent                                                               | Physical fault-injection by exact model/driver; document expected state mapping                             |
| Malicious update/supply chain  | Compromised dependency, Action, NuGet/npm package, kiosk binary, or deployment account    | Lockfiles, Dependabot, audits, CodeQL, CODEOWNERS, protected branches/environments, checksums                                                 | Major-tag Actions and public registries remain supply-chain dependencies; unsigned kiosk build is replaceable                                    | Pin/review dependencies, code-sign installer/binary, verify checksum/signature, least-privilege maintainers |

## Abuse cases that must remain impossible

- A Route Handler accepting or returning the document/ciphertext body.
- A token or signed URL in query strings, telemetry, exception text, or persistent logs.
- Transitioning a terminal session back to an active state.
- Replacing the committed Blob pathname/ETag or consuming twice.
- Parsing bytes before GCM authentication or printing before independent validation.
- Automatically retrying an uncertain spool submission.
- A public route opening the administrator surface.
- Staff logging in to KakaoTalk, email, cloud storage, or entering a visitor's password.

## Review cadence

Re-run the threat model for protocol changes, parser/renderer changes, printer/driver changes,
provider/storage changes, kiosk policy changes, and before every site rollout. Unresolved items are
tracked in `PRODUCTION_BLOCKERS.md` and `REMAINING_RISKS.md`.
